## Exact next step

**Build the Verve meter, and only the meter, before any spender exists.**

1. `int Verve` on `Unit`, defaulted 0, cap 5.
2. Four charge listeners, one per player class, hung off the **event stream** — not off rules
   checking themselves. Conditions are in `VERVE.md`; do not re-derive them.
3. `VerveCharged(unit, source, newTotal, wasted)` and `VerveSpent`, both wired into `CombatLog`
   (there is a reflection test asserting every event type has log coverage — it will fail otherwise).
4. `RunUnit` carries Verve between fights: downed keeps it, **voided loses it with the unit**.

**Do not start the four spenders until the meter has tests.** They are specified to land whole
(`VERVE.md`), and a half-built meter under a half-built spender is the one shape that will not
bisect.

**Two traps waiting specifically for this work**, both of which will otherwise fail silently:

- Adding a field to `Unit` or `RunState` **must** be registered in
  `tests/Faultline.Core.Tests/StateEqualityCoverageTests.cs`. It fails by name if you forget, which
  is the point — but read D-070 first so the failure means something.
- Anti-farm is *"an enemy must be affected"*. **Debris does not exist yet.** Write the check as
  "an enemy was affected", not as "the target was not debris", so it is correct now and stays
  correct when debris lands.

## Traps

Written from scars, not from principle.

**Core has zero package references, and that is load-bearing.** It settled a JSON-vs-grid question
this session: `System.Text.Json` is not in netstandard2.1's BCL, so adopting it would break the prime
directive. Do not add a dependency to `Faultline.Core` without a ruling.

**The shell inferring a Core concept from incidental data is a bug waiting for the second case.**
Twice this session. `DescribeAbility` treated *any* ability with a `Direction` as a charge, so Spear
Thrust rendered as "Charge 3 to (4,0)". `EventText` fell through to `"hold position"` for any
unknown `IntentAction`, so a Rescue telegraph lied. **Neither was catchable by a Core test — Core was
right both times.** Both fallthroughs now have reflection tests standing where they were; add one
rather than a `default` case.

**Test the committed state, not the working tree.** `HEAD` was red for three commits because the
working tree contained an agent's fix that `HEAD` did not. `git worktree add --detach <tmp> HEAD` and
run the suite there before claiming green.

**`GAMEPLAY.md` must never describe behaviour the code lacks.** The Stop hook blocks on Core rule
changes without it. When work is genuinely in flight and does not build, the right answer is to say
so and let the hook fire again — not to write the doc early, and not to disable the hook.

**`Ai.cs` is 1459 lines and is the most contended file in the repo.** Every enemy plan adds a branch.
Put shared behaviour in `Ai.Compute` before the plan switch, as the rescue slot does, rather than
copying into sixteen `Plan*` methods.

**A rescue costs the whole activation**, and `Pits.CanRescue` was always team-agnostic. Before adding
a rule, check whether the rule already exists and only the AI never used it — that was the entire
content of D-072.

## Open questions

Nobody has decided these. They are not disliked decisions; they are genuinely open.

- **`GameState.Momentum`** — Verve supersedes it. Delete the field, leave it inert, or repurpose it?
  Needs a call before the Verve UI ships, or the board will show two meters.
- **The AI does not score new mechanics.** `PlanStalker` and `RushScore` still aim at the nominal
  target, so a Stalker lines up a pit shove on a guarded ally for nothing. Debris will land with the
  same gap. This is `PLAYTEST_FINDINGS` concern #2 and the one most likely to be felt in play.
- **Solo play after a wipe.** D-051 ends the run when one player has nothing left to field. Dealing
  the survivor in solo is the other option and is a design call, not a bug fix.
- **`hz-08-free-kick` needs a turn limit.** D-067 widened a soak-test clause instead; the board fix
  is queued with the dead-round work.
