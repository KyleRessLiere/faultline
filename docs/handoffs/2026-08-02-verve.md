## Exact next step

**Build the Verve meter, and only the meter, before any spender exists.** Spec: `VERVE.md`.

1. `int Verve` on `Unit`, defaulted 0, cap 5, overflow discarded.
2. Four charge listeners, one per player class, hung off the **event stream** — not off rules
   checking themselves. Conditions are in `VERVE.md`; do not re-derive them.
3. `VerveCharged(unit, source, newTotal, wasted)` and `VerveSpent`, both wired into `CombatLog`
   (a reflection test asserts every event type has log coverage — it will fail otherwise).
4. `RunUnit` carries Verve between fights: downed keeps it, **voided loses it with the unit**.

**Then stop and test.** The four spenders land whole (`VERVE.md`), and a half-built meter under a
half-built spender is the one shape that will not bisect.

### The seam exists; two of the four conditions cannot read it yet

`Game.Apply` already runs a post-pass over the finished event list —
[`Ai.ReplanInvalidated(next, events)`](../../src/Faultline.Core/Rules/Game.cs#L199), with the full
stream and the post-command state in hand. That is where the charge pass goes, and it is precedent
rather than a new pattern. **Do not put charges in the thirteen files that build events.**

But the payloads only answer half the question:

| Class | Reads | Self-contained? |
|---|---|---|
| Archer | `UnitAttacked(AttackerId, …, FromHighGround)` | **yes** |
| Wardbearer | `GuardIntercepted(UnitId = the guard, …)` | **yes** |
| Vanguard | `Collision(UnitId, At, ObstacleId, Damage)` | **no — names the collider and the obstacle, not the causer** |
| Threadcaster | `UnitPushed(UnitId, From, To, Path, Kind, Distance)` | **no — same gap** |

"A collision **he** causes" is not derivable from `Collision` as it stands. Decide this before writing
the listener, not during:

- **A — attribute to `state.ActiveUnitId`.** No event churn, correct for every case the spec names,
  and it credits chain collisions to the shover, which is the intent. **Take this one.**
- **B — add a causer to `UnitPushed` and `Collision`.** Cleaner in the abstract, but it changes two
  event schemas, drags in D-070's coverage registration, and touches every test that constructs
  either. Nothing needs it yet, and A does not foreclose it.

A is still *listening* — the pass reads the stream and asks the state whose activation produced it.
It is not a rule checking itself, which is the thing `VERVE.md` forbids.

### Three traps waiting specifically for this work

Each fails **silently** if ignored:

- **Adding a field to `Unit` or `RunState` must be registered** in
  `tests/Faultline.Core.Tests/StateEqualityCoverageTests.cs`. It fails by name if you forget — that
  guard was built two commits ago *because Verve was coming*. Read D-070 so the failure means
  something.
- **Anti-farm is "an enemy was affected"**, not "the target was not debris". **Debris does not exist
  yet.** Phrase it the first way and it is correct now and stays correct when debris lands.
- **`GameState.Momentum` still exists and is still displayed.** Verve supersedes it. Decide its fate
  *before* the Verve UI ships or the board will show two meters. This is an open question below, not
  a decided one.

## Traps

Written from scars, not principles.

**Core has zero package references, and that is load-bearing.** It settled a JSON-vs-grid question
this session: `System.Text.Json` is not in netstandard2.1's BCL, so adopting it would break prime
directive 1. Do not add a dependency to `Faultline.Core` without a ruling.

**The shell inferring a Core concept from incidental data is a bug waiting for the second case.**
Twice this session. `DescribeAbility` treated *any* ability with a `Direction` as a charge, so Spear
Thrust rendered as "Charge 3 to (4,0)". `EventText` fell through to `"hold position"` for an unknown
`IntentAction`, so a Rescue telegraph lied. **Neither was catchable by a Core test — Core was right
both times, and a human found both by playing.** Both fallthroughs now have reflection tests standing
where they were. Add one rather than a `default` case.

**Test the committed state, not the working tree.** `HEAD` was red for three commits because the
working tree held a fix `HEAD` did not. `git worktree add --detach <tmp> HEAD`, run the suite there.

**`GAMEPLAY.md` must never describe behaviour the code lacks.** The Stop hook blocks on Core rule
changes without it. When work is genuinely mid-flight and does not build, say so and let the hook
fire again — do not write the doc early, do not disable the hook.

**`Ai.cs` is 1626 lines and is the most contended file in the repo.** Put shared behaviour in
`Ai.Compute` before the plan switch, as the rescue slot does, rather than copying into sixteen
`Plan*` methods.

**Check whether the rule already exists and only the AI never used it.** That was the entire content
of D-072: `Pits.CanRescue` had always been team-agnostic and `RescueCommand` had always been on offer.

## Open questions

Genuinely undecided — not decisions somebody dislikes.

- **`GameState.Momentum`** — Verve supersedes it. Delete, leave inert, or repurpose? **Needs a call
  before the Verve UI ships.**
- **The AI does not score new mechanics.** `PlanStalker` and `RushScore` aim at the nominal target, so
  a Stalker lines up a pit shove on a guarded ally for nothing. Debris will land with the same gap.
  `PLAYTEST_FINDINGS` concern #2, and the one most likely to be *felt* in play.
- **Solo play after a wipe.** D-051 ends the run when one player has nothing left to field. Dealing
  the survivor in solo is the other option — a design call, not a bug fix.
- **`hz-08-free-kick` needs a turn limit.** D-067 widened a soak-test clause instead; the board fix is
  queued with the dead-round work.
