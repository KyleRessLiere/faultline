## Traps

**`--seed` is inert, so every harness number is n=1.** Nothing in `Faultline.Core` constructs or
consumes an `IRng` for a *fight*; `GameState.Seed` is read only by equality and hashing. Every
deterministic policy produces byte-identical results at seeds 1, 2, 3 and 7. **Any instruction to
"measure across seeds" is currently a no-op**, and a table with a seed column would be a table of one
sample repeated. Real variation needs squad loadout, node list, or `--levels`/`--sweep` — or wiring
the seed into something the rules read, which is a design ruling and not a measurement. This is the
trap Phase 5 walks straight into.

The one exception, and it is new: **the run layer now makes exactly one seeded draw** — the coin a
split vote flips, from `RunState.RngState` (D-117). It is deliberately not the fight seed, so a coin
flip does not reshuffle the enemies behind the next door.

**The AP turn is a net negative across the policy field.** `first-legal` 3→0, `brawler` 6→2,
`careful` 1→0, `shover` 1→5, the three evaluators flat. Only the ability-first policy gained. That is
directionally consistent with the design's intent, but the field-wide picture is bleaker than the
`shover` row alone suggested and **nobody has ruled on whether that is the intended shape.** Combined
with the `--seed` trap, the AP-vs-Bedraggled tension — Bedraggled's whole measured cost landing on the
one policy AP was written to reward — remains a **single sample**. Do not quote these numbers as
though they were a distribution.

**Two writers held `DECISIONS.md` and `GAMEPLAY.md` for most of this session**, which is why seven
rulings spent two commits living in commit messages. It worked only because the drafts were written
down *somewhere* at the time. If you find yourself blocked on a shared doc again: draft into the
commit message and `docs/handoffs/REVIEW_QUEUE.md`, then close it out in a pass of its own — do not
reconstruct from memory a week later, and do not edit the file out from under the other writer.

**`git commit -- <paths>` every time; never `git add -A`.** This repo has been bitten by it four
times, most recently when a battle-screen commit swallowed another writer's `DECISIONS.md` entry.
Every commit this session used explicit pathspecs.

**One Web test is order-dependent and flaky.**
`DevLogTabTests.ExpandingEveryDrawer_IsWithinTheRememberedFlags` fails in a full-suite run and passes
in isolation — reproduced at `45989cc` in a clean worktree, so it is not the map work. CLAUDE.md's
testing standards forbid a test that depends on execution order; this one does. If the Web suite is
red by exactly one test, look here first.
